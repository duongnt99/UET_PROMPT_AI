1. Tổng quan hệ thống

Hệ thống Prompt-Off: Vietnam 2026 là modular monolith Next.js phục vụ hai vòng nghiệp vụ:

  1. Vòng tuyển chọn (online): tạo tài khoản → hồ sơ → đăng ký cá nhân/đội → nộp Audition → reviewer chấm → BTC khóa danh sách → công bố finalist.
  2. Vòng chung kết (trực tiếp): bracket → sprint/pitch → giám khảo chấm → twist → verdict → overlay livestream.

2. Cài đặt và chạy local

2.1. Yêu cầu

  • Node.js 20.9+, pnpm 10+
  • Docker (khuyến nghị) hoặc PostgreSQL local
  • psql / pg_dump nếu dùng script backup

2.2. Các bước

  1. corepack enable && pnpm install
  2. docker compose up -d postgres minio minio-init mailpit
  3. cp .env.example .env — đổi AUTH_SECRET ≥ 32 ký tự
  4. pnpm db:generate && pnpm db:migrate && pnpm db:seed (seed chỉ dev)
  5. pnpm dev → mở http://localhost:3000
  6. Email dev xem tại Mailpit http://localhost:8025

5.3. Reviewer (chấm Audition)

  1. Đăng nhập → /reviewer — danh sách bài được phân công.
  2. Mở bài → /reviewer/[id] — chấm từng tiêu chí 0–10 (bước 0.5), nhận xét (bắt buộc nếu requireReviewComment).
  3. Lưu nháp hoặc Nộp phiếu. Sau nộp, phiếu khóa.
  4. Blind review (mặc định bật): không thấy email/PII thí sinh.
  5. Điểm chuẩn hóa theo trọng số rubric AUDITION → tổng 0–100.

5.4. Giám khảo chung kết (JUDGE)

  1. Đăng nhập judge1@… → /judge.
  2. Vào trận được gán → /judge/matches/[id].
  3. Chấm từng bên (A và B): Khả thi / Sáng tạo / Tác động theo rubric FINAL.
  4. Lưu nháp đủ hai bên → Nộp điểm trận.
  5. Không thấy điểm gộp 3 giám khảo. BTC xem /admin/scoring.

Cần 3/3 giám khảo nộp phiếu. Hòa → TIE_REVIEW / NEEDS_VERDICT, BTC chọn tay (MANUAL_VERDICT).

8.2. Trạng thái đăng ký

DRAFT → SUBMITTED → UNDER_REVIEW → SCORED → LOCKED SUBMITTED / UNDER_REVIEW / SCORED → NEEDS_UPDATE (mở lại) NEEDS_UPDATE → SUBMITTED | DRAFT

8.4. Trạng thái trận chung kết

DRAFT → SCHEDULED → CHECK_IN → READY → SPRINT → PITCH → SCORING → VERDICT → COMPLETED SCORING / VERDICT → TIE_REVIEW | NEEDS_VERDICT (hòa) COMPLETED → có thể PUBLISHED (điểm công khai nếu bật cờ)

  • Một reviewer chỉ một phiếu cho mỗi version bài
  • Một giám khảo một phiếu cho mỗi thí sinh trong trận

10. Vận hành, cron, backup, deploy

10.1. Cron email (bắt buộc production)

* * * * * curl -fsS -X POST https://DOMAIN/api/cron/email -H "Authorization: Bearer CRON_SECRET"

Dev: pnpm email:outbox hoặc xem Mailpit :8025.

10.2. Health & monitoring

  • GET /api/health — uptime check
  • /admin/operations — DB, storage, email failed, incidents
  • /admin/audit — nhật ký thao tác nhạy cảm

10.3. Backup

ScriptMục đích
scripts/backup-db.shpg_dump → backups/*.sql.gz
scripts/restore-db.shKhôi phục (chỉ môi trường riêng)

10.4. Deploy production (tóm tắt)

  1. Server: Node 20, PostgreSQL 16, S3, SMTP, Nginx + HTTPS
  2. git pull && pnpm install --frozen-lockfile
  3. pnpm db:migrate:deploy (backup trước, không seed)
  4. pnpm create-super-admin — tạo admin thật
  5. pnpm build && pm2 start pnpm --name promptoff -- start
  6. Cấu hình cron email. Chi tiết: docs/DEPLOYMENT.md

10.5. Rehearsal

Cuộc thi rehearsal (isRehearsal=true) dùng tập dry-run. Email bị chặn trừ khi ALLOW_EMAIL_IN_REHEARSAL=true.

11. Lưu ý quan trọng

  1. Không seed production — lộ mật khẩu demo và dữ liệu giả.
  2. Email xác minh / mời đội cần SMTP + cron. Local thiếu Mailpit → lỗi kết nối :1025.
  3. HTTPS bắt buộc trên production cho cookie session an toàn.
  4. Giám khảo: Lưu nháp cả hai bên trước khi Nộp phiếu.
  5. Overlay tự refresh; màn /stage/* cần F5 thủ công.
  6. Start timer SPRINT reset về sprintDurationSeconds, không resume từ pause.
  7. publicScoresEnabled=false mặc định — /scoreboard không hiện số điểm.
  8. Export CSV chứa PII — chỉ ADMIN; mọi lần export ghi audit.
  9. File upload private — tải qua signed URL, chặn executable.
  10. Rate limit login/register/upload trên DB (một instance, chưa Redis).
  11. AUTH_SECRET, CRON_SECRET, mật khẩu DB/S3 phải khác local.
  12. Ngày/giải chưa chốt hiển thị “Dự kiến” / “Đang cập nhật”.
  13. Trang /ket-qua hiện là placeholder — chưa có kết quả chính thức.

12. Phụ lục — sơ đồ luồng
