Hệ thống là modular monolith Next.js: một ứng dụng web phục vụ website công khai, thí sinh, reviewer, giám khảo, kỹ thuật sân khấu và Ban Tổ chức. Database PostgreSQL, file S3-compatible, email qua hàng đợi (outbox).

Có thể demo ngay trên local: đăng ký tài khoản, tạo hồ sơ cá nhân/đội, nộp Audition (nháp + nộp), reviewer chấm, BTC xem ranking; trận mẫu PI1 (Đội 7 vs Finalist 10) để giám khảo chấm và overlay hiện tên + timer.
Chưa sẵn sàng phát động 15/09 nếu hiểu “sẵn sàng” = các đội trên internet đăng ký được. Còn thiếu: máy chủ + tên miền + HTTPS + email thật + S3 thật; CMS soạn thể lệ; form mời giám khảo/kỹ thuật; CAPTCHA; và BTC chốt thể lệ / hình thức thi.

4. Cách sử dụng theo vai trò

Base URL local: http://localhost:3000. Mật khẩu demo: xem mục 5.

4.1. Khách (chưa đăng nhập)

  1. Xem thông tin cuộc thi: /, /gioi-thieu, /the-le, /lich-trinh, /faq, /tin-tuc.
  2. Tạo tài khoản: /dang-ky (họ tên, email, mật khẩu ≥ 10 ký tự).
  3. Xác minh email qua link (nếu SMTP chạy).
  4. Đăng nhập /dang-nhap. Quên mật khẩu: /quen-mat-khau.
  5. Xem finalist / scoreboard / livestream khi BTC bật cờ tương ứng.

4.2. Thí sinh / đội (PARTICIPANT)

Menu: Tổng quan, Hồ sơ, Đội thi, Đăng ký, Audition, Thông báo, Biên nhận.

  1. Hồ sơ — điền họ tên, trường, mã sinh viên (bắt buộc trước khi nộp đăng ký).
  2. Đăng ký — tạo nháp Cá nhân hoặc Đội. Đội: đặt tên, mời email. Sĩ số khi nộp: 2–4 thành viên đã chấp nhận.
  3. Đồng ý thể lệ + xử lý dữ liệu → Nộp hồ sơ → nhận mã PO26….
  4. Biên nhận — in trang /dashboard/bien-nhan.
  5. Audition — chỉ khi hồ sơ đã SUBMITTED (hoặc ELIGIBLE / UNDER_REVIEW / …). Autosave khi rời ô. Bắt buộc: tiêu đề, bài toán, giải pháp, cách dùng Gemini, cam kết nguyên gốc. Chỉ nhóm trưởng nộp bài.
  6. Thành viên đội vào /loi-moi-doi khi đã đăng nhập.

Một người chỉ thuộc một hồ sơ đang hiệu lực. Không có role “đội” riêng — đội = nhiều PARTICIPANT.

4.3. Reviewer (chấm Audition)

  1. Đăng nhập → /reviewer.
  2. Mở bài được phân công, chấm từng tiêu chí 0–10 (bước 0.5), nhận xét, lưu nháp, nộp.
  3. Điểm chuẩn hóa theo trọng số, tổng 0–100. Không thấy email thí sinh nếu blind review bật.

4.4. Giám khảo chung kết (JUDGE)

  1. Đăng nhập judge1|2|3 → /judge. Badge “Đã nộp phiếu” / “Chưa nộp”.
  2. Vào trận (ví dụ PI1). Chấm từng bên (Đội 7 và Finalist 10): khả thi / sáng tạo / tác động.
  3. Bấm Lưu nháp cho đủ hai bên (thấy “Đã lưu nháp · tổng …”) rồi Nộp điểm trận.
  4. Thành công: khung xanh “Phiếu của bạn đã được ghi nhận” + điểm từng tiêu chí.
  5. Giám khảo không thấy điểm gộp 3 phiếu. BTC xem /admin/scoring. Công chúng /scoreboard không hiện số (cờ tắt).

Công thức: (raw/10)×trọng số; tổng giám khảo; điểm trận = trung bình các phiếu đã nộp. Cần 3/3. Hòa → TIE_REVIEW, BTC chọn tay.

4.5. Kỹ thuật sân khấu (TECH_OPERATOR)

  1. Đăng nhập tech@ → /admin/operations: Start / Pause / Resume timer sprint của trận đang SPRINT/PITCH/SCORING/READY.
  2. Màn sân khấu (cần đăng nhập): /stage/current-match, /stage/timer, /stage/twist, /stage/verdict. Stage không tự refresh — F5.
  3. Overlay (không login, để OBS Browser Source): /overlay/current-match (thêm ?compact=1 nếu cần), /overlay/scoreboard.

7. Trạng thái nghiệp vụ (rút gọn)

Đăng ký: DRAFT → SUBMITTED → NEEDS_UPDATE | UNDER_REVIEW | ELIGIBLE | INELIGIBLE | SELECTED | NOT_SELECTED | WITHDRAWN | LOCKED

Bài nộp: DRAFT → SUBMITTED → UNDER_REVIEW → SCORED → LOCKED; NEEDS_UPDATE để mở lại.

Phiếu chấm: ASSIGNED → DRAFT → SUBMITTED → LOCKED; reopen chỉ SUPER_ADMIN + lý do.

Trận: DRAFT → SCHEDULED → CHECK_IN → READY → SPRINT → PITCH → SCORING → VERDICT → LOCKED → PUBLISHED → COMPLETED; thêm TIE_REVIEW / NEEDS_VERDICT.

Uniqueness: một seat (user, cuộc thi); mã hồ sơ unique; một reviewer một version bài; một phiếu GK một thí sinh trong trận.

8. Chạy local (nhắc nhanh)

  1. Node 20.9+, pnpm 10+, PostgreSQL (hoặc Docker postgres/minio/mailpit).
  2. cp .env.example .env — đổi AUTH_SECRET ≥ 32 ký tự nếu máy dùng chung.
  3. pnpm install && pnpm db:generate && pnpm db:migrate && pnpm db:seed
  4. pnpm dev → http://localhost:3000
  5. Không seed trên production. Migration production: pnpm db:migrate:deploy có kiểm soát, backup trước.

Kiểm thử đã chạy 14/08/2026: lint, typecheck, unit/integration, build, e2e Playwright (trang chủ, login, dashboard, không lộ PII public).

9. Lưu ý quan trọng

  1. Không “export localhost” ra internet. Cần server + DNS + HTTPS. Cookie đăng nhập yêu cầu HTTPS khi lên production.
  2. Không chạy seed trên production — lộ mật khẩu demo, dữ liệu giả, tài khoản local.
  3. Email xác minh / mời đội / biên nhận phụ thuộc SMTP và cron. Local thiếu Mailpit thì mail fail (đã gặp ECONNREFUSED :1025).
  4. CSP production không có unsafe-eval; development cần unsafe-eval cho React (đã chỉnh next.config.ts).
  5. Giám khảo phải Lưu nháp cả hai bên trước khi Nộp. Overlay tự cập nhật; màn /stage phải F5.
  6. Start timer sprint reset về 45 phút, không tiếp tục từ thời điểm pause.
  7. Điểm công khai tắt mặc định (publicScoresEnabled = false).
  8. Export CSV chứa PII — chỉ ADMIN/SUPER_ADMIN; có audit.
  9. File upload chặn executable; object private, lấy bằng URL ký.
  10. Rate limit login/register/upload trên bảng DB — đủ một instance, chưa Redis.
  11. Production: AUTH_SECRET, CRON_SECRET, mật khẩu DB/S3 phải khác local.
  12. Nội dung “chưa chốt” phải hiện Dự kiến / Đang cập nhật — không bịa ngày giải livestream.

11. Đề xuất việc làm tiếp (gợi ý ưu tiên)

Trước phát động (nếu mốc 15/09 giữ)

  1. Chốt câu 1–9; khóa thể lệ và hình thức thi trên settings.
  2. Deploy staging (HTTPS + Postgres + SMTP + S3), tạo SUPER_ADMIN thật, không seed.
  3. CMS admin: sửa thể lệ / FAQ / tin / hướng dẫn Audition.
  4. Form mời ADMIN, TECH, REVIEWER, JUDGE.
  5. Nút upload trên form Audition; bật CAPTCHA.
  6. Mở đăng ký trên domain chính thức.

Trước chung kết (tháng 10–11)

  1. Ngân hàng đề + Reveal; gán đề/twist cho trận.
  2. UI đổi pha trận, chốt thắng, timer PITCH/VERDICT.
  3. Stage auto-refresh; overlay twist; trang kết quả.
  4. Rehearsal trên competition riêng, runbook ngày thi.
